# Experiments (2026-10-02): crop similarity — diagnosis, a rejected grid, a larger query set

The earlier scorecard reported crop similarity at **nDCG 0.62 / R@10 0.52**, from **5 queries** (one crop
per species). Per-query nDCG ranged from 0.36 to 0.87, so that number could not support conclusions.

## 1. Diagnosis on dev (65–80 crop queries: 4 references × 3–4 fixed boxes per species)

| scoring | nDCG@10 | R@10 |
|---|---|---|
| crop vector vs all stored views (raw, no cut-off) | 0.801 | 0.751 |
| … global views only | 0.777 | 0.735 |
| … region views only | 0.804 | 0.754 |
| whole-image reference (same refs), global | 0.769 | 0.763 |
| live `find_similar` (min_cos 0.55) | 0.779 | 0.722 |
| live with min_cos 0.50 / 0.45 / 0.40 | 0.782 | 0.725 |

- The similarity cut-off is not the cause. Relaxing it changes nothing, and LinkedIn crops return
  0 flower hits at every cut-off.
- Crop queries perform like whole-image reference queries. The limit is how finely CLIP ViT-B/32 separates
  flower species in this set, not region coverage.
- Live results are slightly lower than raw scoring because `find_similar` collapses near-duplicates (shown as
  "+N dup"), so collapsed relevant items do not count toward recall@10.

## 2. Candidate: denser region views — rejected

Each eval asset was given additional CLIP views in memory, and the same queries were re-scored:

| | current views | + 3×3 grid | + 3×3 + overlapping half windows |
|---|---|---|---|
| dev (80) | 0.759 / 0.702 | 0.755 / 0.702 | 0.757 / 0.702 |
| test (80) | 0.773 / 0.730 | 0.774 / 0.735 | 0.780 / 0.740 |

There is no gain on dev, and the cost is real: +516 ms of CLIP time per image at analysis and 9–18 extra
vectors per image (about 3× the image index). **Not adopted.**

## 3. Protocol change

`scripts/eval_image_library.py` now uses 4 references × 4 fixed boxes per species (80 crop queries on
test), generated by the same procedure as the dev diagnosis. Nothing was tuned on test.

Result on test with the live path: **nDCG 0.735, R@10 0.667**. This is below target (0.75 / 0.80) and is
the honest number. All other families are unchanged.

Next levers, none available here: a stronger image encoder (e.g. ViT-L/14 or SigLIP, which cannot be
provisioned because HF returns 403), or user feedback (confirmed group members as positives).
